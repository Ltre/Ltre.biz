# v1.3.0 完成，4 点要求全部落实

## 1. 商品列表支持 全选 / 反选 / 取消选择
结果区按钮由单个「全选可采集」改为 **全选 · 反选 · 取消选择 · 执行采集 · 导出JSON**。三个操作都只作用于"可采集项"（未排除、未采集），已排除/已采集的不受影响。

## 2. 风控验证码：改为 AI 自动识别并完成验证
不再"识别后暂停等人工"。新的自动处理链路：

- **AI 视觉模型**根据页面截图 + DOM 元素清单给出可执行方案（验证类型、动作、视口坐标、滑块目标位置、需输入的文字），新增 `solveRiskChallenge` 替代原来的"只识别不求解"。
- **优先走 `chrome.debugger`**（manifest 已加 `debugger` 权限）注入真实鼠标/键盘输入事件，可以操作跨域 iframe 内的验证码；调试器不可用时回退页面内 DOM 自动化（拖动滑块/点选图片/输入文字）。
- 搜索、扫描、翻页、详情页、采集前检查所有环节遇验证都会自动处理并**重试原操作**，最多自动尝试 3 次；通过后任务自动继续。
- AI 未启用、未选视觉模型，或自动处理多次失败时才暂停人工处理。

两点要提前说明：① Chrome 会为 `debugger` 权限显示警告，这是自动过验证码的必要权限；② 如果 Temu 的验证码在跨域 iframe 里且调试器不可用（比如你正开着开发者工具），浏览器安全隔离不允许脚本触达 iframe 内部，这种情况仍会暂停人工——这是平台的硬边界，不是没实现。

## 3. D1 binding 名称已修正
`package.json` 两个迁移命令已由 `AI_RELAY_DB` 改为 `DB`，与 `wrangler.jsonc` 一致。**本次实测通过**：`npm run db:migrate:local` 成功执行 0001_init.sql（15 条命令）。README 和初始化指南中的相关命令也同步修正。

## 4. 后台渠道/模型：编辑、删除、启用/停用
- 服务端新增 `PATCH/DELETE /api/admin/models/:id` 和 `DELETE /api/admin/channels/:id`。
- 后台每个已登记模型自带编辑表单（模型 ID/显示名/视觉/成本）+ 保存、删除、启用/停用按钮；渠道行增加删除按钮。
- 模型和渠道的启停都会立刻决定"是否给用户使用"：停用后从用户模型列表消失，直接调用也返回 403。
- 有调用记录的渠道/模型**只能停用、不能删除**（保留用量统计），界面会提示。
